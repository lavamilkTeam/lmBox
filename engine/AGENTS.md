# Python 几何计算引擎

修改本目录前，先阅读根目录 [AGENTS.md](../AGENTS.md)，并应用 `code-boundary-standards`。涉及跨语言数据或通信时，先读 [contracts/AGENTS.md](../contracts/AGENTS.md)；涉及任务、文件或进程管理时，同时读 [src-tauri/AGENTS.md](../src-tauri/AGENTS.md)。

## 当前状态与职责

已实现 graphics v2 到钢网/定位底板网格的计算、编辑及优化、网格检查和单次 JSONL 进程入口，支持 STL、SVG、DXF 序列化。实体 CAD/STEP 和切片仍未实现。下方完整目录仍含后续规划，按实际功能逐步建立模块。

Rust 负责导入、解包、Gerber/DXF 格式解析、图层识别和业务操作。Python 接收 Rust 输出的版本化图形中间表示（IR），负责图元求值、轮廓合成、开孔补偿、定位结构、实体网格及几何检查。

- Python 不再次解析原始 Gerber/DXF，不管理项目、用户配置、业务任务队列或缓存目录。
- Rust 解析文件语法、坐标与图形命令；Python 根据 IR 计算几何。IR 需要完整保留极性、绘制顺序、孔径宏、变换及圆弧等语义，不能退化为矩形列表。
- 切片器由 Rust 调用；本引擎不负责管理切片进程或拼接打印机启动、结束 G-code。
- Vue 只渲染几何结果，不另做一份用于生产的开孔或模型算法。

## 目标目录：模块化单体，按能力组织

Python 采用 Feature-first：同一业务能力的轮廓、补偿、网格算法放在一起。当前只有模板生成和几何检查两个边界；不先拆成全局 `contours/`、`mesh/` 等技术层，也不拆成多个服务。

```text
engine/
├── AGENTS.md
├── pyproject.toml                 # 引擎依赖、版本及检查配置，待建立
├── src/lmbox_geometry/
│   ├── __init__.py                # 最小包入口
│   ├── __main__.py                # 进程启动
│   ├── runner.py                  # 单次请求协调，串联计算与检查
│   ├── contracts/                 # 跨能力输入输出类型，与根 contracts 对齐
│   ├── features/
│   │   ├── stencil/               # 模板生成能力
│   │   │   ├── __init__.py        # 小型公开入口
│   │   │   ├── _pipeline.py       # 本能力内的计算步骤
│   │   │   ├── _contours.py       # 图元求值、圆弧与极性合成
│   │   │   ├── _offset.py         # 开孔补偿及定位结构
│   │   │   └── _mesh.py           # 挤出、三角化与模型输出数据
│   │   └── inspection/            # 几何质量检查，内部实现同样私有
│   └── runtime/
│       ├── protocol/              # JSONL 通信、协议校验与编解码
│       └── artifacts/             # 任务产物读取、序列化与文件写入
└── tests/                        # 公共接口、协议与几何回归测试
```

各能力包用自己的 `__init__.py` 暴露少量稳定函数、输入输出类型和错误类型。实现文件使用 `_` 前缀并保持私有；其他包不得直接导入私有文件，也不得通过根包转导出整个子树。复杂算法可拆为私有模块，不必为每个函数建立新包。

## 依赖方向与接口

```text
__main__ → runner
runner → features/stencil、features/inspection、runtime、contracts
features/* → contracts
runtime/* → contracts
```

`runner` 通过公开入口调用模板生成，再将结果交给几何检查。两个 feature 不互相导入，`runtime` 不依赖 feature，`contracts` 不依赖算法或运行时。算法不能反向依赖 `runner`、`runtime` 或进程入口，也不得理解前端状态、项目存储及线上的消息信封。

- `runner` 只协调一次请求内的运行，`stencil/_pipeline.py` 只组合本能力内的计算；都不承担 Rust 的队列、重试、任务取消和缓存策略。
- 算法以明确的几何数据和参数为输入，返回几何结果与结构化诊断，尽量保持纯函数。时间、随机数、环境和文件路径不应暗中影响结果。
- feature 专有类型归属本能力包，从公开入口使用；跨能力输入输出类型放在引擎 `contracts/`。跨语言格式以根目录 `contracts/` 为准，不能在这里另立一套通信契约。
- 第三方几何库的调用和异常转换留在使用它的能力包内，避免把库对象泄漏到协议或其他模块。需要替换或测试的地方再建立窄接口，不提前建设通用插件框架。
- 不创建承接各种无关逻辑的 `utils`、`common`、`shared` 包；新增能力应有明确所有者和单向依赖。
- 后续能力先放在所属 feature，只有多个能力确实复用时才提取有具体职责命名的几何模块。不要为未来可能的复用先建立通用几何框架。

## 几何正确性

- 统一使用协议规定的毫米坐标、原点与轴方向。Rust 负责单位归一化；Python 校验单位与有限数值，不猜测单位、不重复缩放。
- 按 IR 中的图层局部极性和绘制顺序合成，不将所有开孔简单求并集。宏表达式及参数由 Rust 完成格式层面的求值；Python 只接收已求值的基元和曝光顺序，计算几何组合。未求值的源格式表达式应拒绝，禁止使用 `eval`。
- 圆弧方向、整圆、宏变换、重复图形、旋转和镜像均需保留语义。离散容差与布尔运算精度必须明确且可复现，不能取决于预览缩放。
- 明确开孔补偿的正负含义，统一 offset、连接样式及最小尺寸规则。补偿造成孔消失、相邻孔合并或连接过窄时，返回可定位的诊断，不能静默产出另一种形状。
- 镜像由参数明确指定，不能因底层名称自动重复镜像。外轮廓、孔洞绕向以及镜像后的绕向由同一套规则处理，确保孔洞仍是孔洞。
- 对自相交、未闭合、退化轮廓以及极小特征明确拒绝或报告修复；修复必须在约定的误差范围内，记录实际改变，不随意改设计尺寸。
- 先得到最终二维轮廓，再供 2D 预览和 3D 挤出共同使用。预览网格可以简化，但导出使用的制造几何必须可追溯到相同参数和轮廓。
- 网格需要检查法向、闭合性、非流形边、退化三角形、尺寸与孔洞保留情况。几何有效不能替代切片后的可打印性验证。

## Rust 与 Python 的进程协议

- 以版本化 JSONL 作为控制通道。`stdout` 只输出合法协议消息，诊断日志写 `stderr`；禁用会污染 `stdout` 的第三方进度条和打印。
- 每个请求和响应携带契约规定的协议版本、项目、任务及输入修订标识。协议版本不支持或输入不合法时，返回结构化错误；不得继续使用默认值计算。
- 大型 IR、二维产物及网格通过 Rust 为该任务分配的目录交换。路径和产物类型受协议约束；Python 不接受任意外部输出位置，不读取其他工程或覆盖其他任务产物。
- 文件读取、输出和序列化由 `runtime/artifacts` 的适配边界处理，消息由 `runtime/protocol` 处理。算法接收已解析的数据并返回内存结果；`stencil/_mesh.py` 返回模型数据，实际文件写入不混进几何函数。
- 临时产物写完并校验后再声明完成，失败时不得把半成品报告为成功。Rust 负责进程超时、取消、终止和目录清理；旧修订结果由 Rust 拒收。
- 相同输入、参数、容差和引擎版本应产生等价几何。引擎版本和影响输出的依赖版本应可追踪，并供 Rust 纳入缓存键；算法变更必须更新对应版本或缓存失效信息。
- 所有示例结果必须标明来源，不能在计算失败时用示例几何冒充用户模型。

## 验证与维护

创建 `pyproject.toml` 和实际引擎时，同步建立 `pytest`、`ruff`、`import-linter` 的配置、模块边界规则及可执行检查命令；当前已建立这些检查，后续以实际配置为准运行检查，并保留根目录要求的 `npm run check`。

测试以各包公开入口和进程协议为主。只为复杂私有算法设置必要的局部测试，不为测试扩大公开接口，也不跨包导入私有实现。至少覆盖：

- 单位与尺寸、极性顺序、圆弧/整圆、宏与重复变换、镜像和孔洞绕向。
- 补偿后孔消失或合并、极小间隙、退化或无效轮廓的明确诊断。
- 2D 与 3D 轮廓一致、尺寸和体积合理、网格闭合，以及相同输入的可复现性。
- 不兼容协议、损坏输入、非法路径、输出失败及严格的 JSONL 输出。

测试夹具使用仓库内可共享的数据，不能依赖开发者 Downloads 中的绝对路径。比较尺寸、拓扑和容差范围内的几何行为，不用会被浮点或三角形排序变化干扰的无意义快照锁死实现。

## 当前实现与执行

- `features/stencil` 公开 `build_preview`，用 Shapely 合成轮廓，用 trimesh/earcut 挤出网格。支持基本 flash、宏曝光、圆孔径 stroke、圆弧、区域、极性顺序及全图重复；非圆/带孔描画明确拒绝。
- 外框可按图形范围或闭合板框生成矩形/随形轮廓；圆弧离散最大弦误差为 0.01 mm。网格支持预览和 STL 输出，不是 STEP 实体，也不表示已完成切片验证。
- 补偿导致孔消失、合并/分裂、开孔越界，或留下悬空材料孤岛时失败；不静默修复自交及未闭合轮廓。
- `features/inspection` 只接收 contracts 中的网格数据，校验闭合性、法向、退化面和体积；`runner` 协调生成、检查，再由 `runtime/artifacts` 原子发布任务内固定产物。
- `contracts` 校验共享 preview/graphics schema；`__main__` 只输出一条 JSONL 响应，失败诊断写 stderr。Rust 分配工作目录并管理进程。
- 首次安装 `npm run setup:geometry`。运行 `npm run check:geometry`（ruff、import-linter、pytest）；预览跨端测试另运行 Rust 检查和 `npm run check`。


## 编辑、打印优化及底板（算法 0.2.0）

- `build_preview(ir, settings, edits=None, outline=None)` 是模板 feature 的公开计算入口。`_editing`、`_frame`、`_solid` 为其私有实现，已有 import-linter 约束。公共数据保持库无关，不导出 Shapely/Manifold 对象。
- 实例按重复行、重复列、源对象索引枚举，与前端一致。仅 dark 对象可编辑；绕原始对象面积中心缩放、旋转，再位移、局部补偿及开孔缩放。镜像最后绕外框包围盒中心作用于整个模型和显示轮廓。clear 操作仍按顺序消去此前曝光。
- 密孔错排只处理在间隙阈值内有邻居的矩形孔，按 Y/X/实例 ID 稳定排序，沿长轴交替偏移并缩小；不声称复现外部软件的专有算法。之后按尺寸阈值分割大孔、保留连接筋，再对每个小孔圆角。全局补偿在曝光合成后应用。局部优化是完整覆盖，没有局部覆盖才使用整层默认值。
- 喇叭孔保持 PCB 接触面孔形，上表面按百分比扩大；由 Manifold3D 生成真实斜壁与布尔差。合并、越界、消失、孤岛、过大圆角及不一致的相连孔喇叭比例明确失败。
- 板框使用区域或闭合描画中心线，不用描画线宽冒充板边；有分叉、未闭合、多板、内孔及重复板框拒绝。矩形支持各边加宽及四角 R/C 尺寸；随形采用统一边距，拒绝非零独立边宽和四角参数。
- 定位底板由底层、PCB 深度的定位槽、间隙、可选右侧卸板槽和向外扩张的取件斜口组成。Manifold 布尔运算后必须为单一连通实体。斜口按槽形中心缩放形成，不宣称任意异形槽均为恒定 45 度倒角。
- inspection 校验有限坐标、闭合、法向、退化面及正体积；直壁网格与解析面积×厚度核对，变截面网格与实体内核体积独立核对。三角面仍限制为 500000。
- `runtime/artifacts` 对已通过检查的网格生成 ASCII STL；SVG/DXF 输出同任务二维轮廓，明确毫米单位。钢网导出接触面；底板从顶面内侧 0.000001 mm 截面提取，包含槽和斜口，不将未加工板框替代实际结果。

- 算法 0.2.2 的反比缩放在 `_solid` 内生成上下两截面及真实斜壁，默认只扩大上口；开启后等量缩小下口。下口轮廓同步用于对象命中、材料轮廓与 SVG/DXF，STL 保留上下截面与孔壁。不能用二维描边代替实体变化；测试对原生网格和导出 STL 的中间高度截面独立量测。

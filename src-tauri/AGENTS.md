# Rust 桌面与业务层

本目录已有单 crate Gerber/ZIP 导入库、浏览器 WASM 薄入口、graphics v2 和 import v1 类型及测试；已有本地模型预览 CLI 和 Python 单次任务调用；Tauri 桌面宿主、持久任务队列及工程存储尚未实现。下列完整目录是目标结构，不代表全部已有能力。先读 [根 AGENTS.md](../AGENTS.md) 并应用 `code-boundary-standards`。后端采用**模块化单体，按业务能力组织（Feature-first）**，以单 crate 起步，不提前拆成多 crate 或微服务。

## 所有权与边界

- Rust 负责导入、源文件管理、Gerber/DXF 解析、工程与配置、任务调度、Python 和切片器进程管理、缓存与导出。
- Rust 解析格式语法和格式语义；Python 负责轮廓化、几何布尔运算、开孔补偿、挤出、网格生成及几何质量检查。不要在 Rust 或前端重复实现这些制造几何算法。
- 先实现明确支持的格式范围。未支持的命令或实体必须返回可定位的错误，不得静默丢弃后产出貌似完整的模型。DXF 兼容可以分阶段接入。
- 前端仅经 `src/platform/desktop` 调用命令与订阅事件。跨前端边界先读 `../src/AGENTS.md`；跨计算边界先读 `../engine/AGENTS.md`；修改通信数据或 IR 先读 `../contracts/AGENTS.md`。

## 规划目录

```text
src-tauri/
├── AGENTS.md
├── Cargo.toml
├── tauri.conf.json
├── capabilities/
└── src/
    ├── main.rs           # 桌面启动入口
    ├── lib.rs            # crate 入口与 Tauri 初始化
    ├── app.rs            # 依赖组装、跨 feature 流程协调
    ├── commands/         # Tauri 命令与事件适配，保持薄入口
    ├── features/
    │   ├── board_import/ # ZIP/独立文件校验、图层识别、Gerber/DXF 解析
    │   ├── project/      # 工程状态、参数、来源、保存与版本迁移
    │   ├── stencil/      # 建模用例、输入版本与产物决策，算法调用 Python
    │   └── slicing/      # 切片用例、打印配置、结果校验与导出决策
    ├── runtime/
    │   ├── jobs/         # 排队、状态、取消、超时等任务执行设施
    │   ├── python/       # Python worker 进程与通信
    │   ├── storage/      # 文件、工程/产物读写、缓存与原子写入
    │   └── slicer/       # 外部切片器进程和配置格式适配
    └── contracts/        # 根 contracts 定义的生成绑定/映射
```

每个 feature 由 `mod.rs` 声明最小接口，内部 `service.rs`、`parser/`、`types.rs` 等按真实需要增加并保持私有；不要照目录树批量建立空文件。同一 feature 的业务、解析、校验和相关类型就近组织，不在全局 `services/`、`models/`、`repositories/` 中按技术层摊开。

跨模块通过 `mod.rs` 的最小公开入口调用；crate 内可见性优先 `pub(crate)`，不要为测试扩大对外可见性。`lib.rs`、生成绑定与 Tauri 要求的入口遵循框架约定，不借此暴露整个内部目录。

依赖方向为 `commands → app → features → runtime 公开接口 → contracts`。features 也可直接使用 contracts 的数据定义。具体规则：

- feature 互不直接导入，包括类型与私有文件；`app.rs` 协调导入、工程、建模与切片，使用返回值或 contracts 定义交换结果。
- feature 不依赖 Tauri 或具体进程/文件实现；runtime 声明有实际用途的窄 trait，app 注入具体实现。测试替身实现这些 trait，勿为每个函数建立抽象。
- runtime 不反向依赖 features；contracts 不依赖 features、runtime、commands。不要通过协议模块绕过业务所有权。
- `jobs` 管执行生命周期，`python`/`slicer` 管对应子进程和协议；业务中的失效判断、产物是否可导出等策略留在相应 feature，跨 feature 决策由 app 协调。
- 不新建泛化的 `common`、`utils` 容器，不把跨模块协调下沉成相互引用。

## 浏览器接入

- `browser.rs` 是仅在 wasm32 启用的薄 ABI，通过 `features/board_import` 公开入口接收受控字节；不在 ABI 中实现解析、解包或业务策略。
- `board_import::import_board` 处理 ZIP 及独立文件，按文件名识别图层并返回 IR 或文件级诊断。不支持的格式、空几何和失败图层不能伪报为成功几何。
- ZIP 使用纯 Rust 解压依赖，在内存中处理；检查文件数量、单文件和展开总大小、实际读取大小、CRC、路径穿越、绝对路径、链接与重复文件名，不向磁盘解压。
- 浏览器 Worker 管理本次计算的超时和取消；原生任务调度、工程保存仍未实现。源文件不会发送到远程服务。
- 解析器保留 D01/D02/D03 模态，G54 仅选择孔径，不产生额外 flash。当前 G74 单象限圆弧和混合范围的重复块明确拒绝；仅支持全图重复，以防无声丢图。

## 解析与 IR

- `features/board_import` 内的解析实现接收受控输入，显式解释单位、坐标格式、零省略、模态状态、孔径定义与格式中的表达式；输出使用约定单位和坐标系的 IR。
- IR 必须表达线段、圆弧、区域、闪光/描画、正负极性、绘制顺序、孔径宏求值后的参数、变换与步进重复；遵循协议对各项的明确约定。不可只输出矩形焊盘、包围盒或截图。
- Rust 消解文件格式语义，Python 消解几何：例如 Rust 给出宏的已求值图元与曝光顺序，Python 计算其实际轮廓和布尔结果。重复与变换可按协议显式保留，不必在 Rust 提前展开巨量图形。
- 原始文件、解析 IR、Python 产生的二维预览和网格须可追溯；2D 预览与建模共享同一输入语义，不能各自另写一套 Gerber 解释逻辑。
- IR 和进程协议有独立版本，兼容性在边界验证。禁止跨语言手抄后任其漂移，遵循 contracts 的生成、校验和测试约定。

## 工程、任务与产物

- Rust 是工程数据事实来源。导入时保存受控源文件副本及标识，工程持久化记录来源、设置与产物引用；不能只保存文件名或前端 File 对象。
- 区分预览显示设置、模型设置和切片设置。网格开关、相机和透明度等显示变化不触发几何任务；模型或切片输入变化按各自依赖使结果过期。
- 每个任务关联工程 ID、任务 ID 和输入修订号/指纹。完成时核对工程仍存在且输入仍匹配，过期任务不得覆盖当前模型，多标签任务不得串写。
- 定义排队、运行、成功、失败、取消等状态及合法转移。取消和超时须传达给实际 worker/切片器，等待进程回收并清理临时输出；不能只修改界面状态。
- `runtime/python` 通过结构化协议传递参数、进度和错误。大图形与网格使用受控 artifact 引用，避免塞进事件或 JSON 长消息。协议输出与诊断日志分流，错误保留阶段及可定位信息。
- Rust 管进程启动、退出、异常、超时和恢复；可执行路径与参数分开传递，不拼接 shell 命令。若 worker 常驻，明确单任务串行或并发规则，禁止不同任务混用未标识输出。
- 模型缓存键包含源内容/IR 指纹、模型设置、算法与协议版本、容差；切片缓存另包含模型指纹、切片器版本与配置。不能用文件名或修改时间单独判定复用。
- 产物先写临时位置，校验成功后原子登记。导出与切片仅接受匹配当前输入且已完成的产物，不使用残缺、取消或过期结果。
- 切片可调用成熟外部引擎，由 `runtime/slicer` 负责进程和配置适配、`features/slicing` 负责业务用例。未接入真实切片器时不得生成伪 G-code，也不得将示例路径称为用户切片结果。

## 文件与持久化

- ZIP 校验文件数、实际展开大小、路径穿越、绝对路径及链接；规范化目标路径后仍需确保位于本工程目录。重复条目与覆盖行为必须明确，不信任文件扩展名即代表有效格式。
- 导入清单与解压读取均有资源限制；解析异常不得留下可被误用的成功工程或模型。
- 工程与产物通过受控 ID 定位。来自 UI 或 worker 的路径不能直接获得任意读写权限；导出到用户选择的目标通过桌面文件接口完成。
- 保存应原子替换并带格式版本；版本迁移规则在 `features/project` 内完成，通过 `runtime/storage` 接口落盘，避免 UI 直接修改磁盘工程结构。

## 验证

- 通过模块公开行为测试解析结果、工程状态和任务结果；外部文件/进程在有替换需求的接口处隔离，不模拟内部调用细节。
- 解析夹具覆盖单位、坐标模式、圆弧、区域、宏、极性和重复；错误夹具验证不静默丢图。几何数值正确性属于 Python 测试，Rust 验证协议及结果接入。
- 验证导入资源限制、保存恢复、worker 异常、取消超时、乱序任务结果、多工程隔离及缓存失效。用真实支持范围内的样例贯通导入、解析与 Python 调用。
- 存在 `Cargo.toml` 后，在 `src-tauri/` 下按实际工程配置运行 `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`；另按根规范在仓库根目录运行 `npm run check`，涉及协议时运行对应协议检查。
- 当前解析器覆盖基本孔径、已求值宏、线/弧、区域、极性、单位归一化和全图重复字段；不能据此宣称完整 Gerber/DXF 支持。
- `cargo run --example dump_ir` 输出 `tests/fixtures/demo.gbr` 的 IR；前端示例 JSON 必须与该输出一致，由集成测试验证。混合形状样例保留在 `preview-shapes.gbr`。
- 新增能力时同步记录实际支持范围与验证结果。

## 当前模型预览入口

- `bin/preview.rs → app::build_preview → features/stencil + runtime/python`；应用层协调业务验证和外部进程，feature 不访问文件或启动 Python。
- CLI 首行读取 preview v1 请求，stdin 关闭即取消。Python 由 Rust 启动并在取消或 60 秒超时后终止、回收。临时任务目录只包含固定名称文件，完成/失败后清理。
- 大 IR 和网格通过任务目录交换，Python JSONL 只返回身份和产物名称；Rust 核对关联信息后读取受限大小的网格。浏览器适配最多同时运行两个任务。
- 原生测试需要先运行 `npm run setup:geometry`。本入口面向本地开发预览，并非已完成 Tauri 桌面打包或工程持久化。


## 编辑及导出入口

- preview v1 可选编辑扩展由 typed serde 结构接收，并在 stencil 业务边界检查参数范围、唯一编辑 ID、板框版本/规模及允许的导出格式；Python 再按同一共享 schema 校验几何输入。
- Rust 继续拥有本地任务目录、子进程与结果读取。Python 返回固定 `mesh.json`，导出文本位于同一受限产物内；Rust 抽取 stl/svg/dxf 格式与内容，拒绝请求和结果格式不符，不开放任意文件路径。
- 前端每次导出带新的任务身份并核对当前修订；取消、超时、并发数和 32 MB 产物限制同模型预览。现阶段仍为本地开发适配，未增加持久任务仓库或 Tauri 宿主。

- `inverseTaper` 可选布尔值默认为 false；业务校验拒绝开启反比缩放且喇叭口比例达到 200% 的请求，完整传递整层及局部优化到 Python，不在 Rust 计算截面。

- XY 缩放字段按共享 schema 提供兼容默认值并完整转发；业务校验模式枚举、有限数值和上下反向模式的小于 200% 限制。原生集成测试覆盖三种模式返回的实际轮廓尺寸。半部裁切与缩放仍归 Python。
